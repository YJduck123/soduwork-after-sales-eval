# 输出契约

输出是一个 JSON 数组，每个输入工单恰好一条，不遗漏、不增加。默认写入 `results.json`；返修时另存新版本文件并保留旧版。

## 字段

| 字段 | 类型 | 约束 |
|---|---|---|
| `case_id` | string | 与输入工单编号完全一致，数组内唯一 |
| `action` | string | `退货退款`、`直接退款`、`补发配件`、`补充材料`、`物流核查`、`人工复核` 之一 |
| `refund_cents` | int / null | 退货退款、直接退款填计算出的整数分；补发配件填 0；其余为 null |
| `freight` | string | `商家`、`买家`、`待定`、`不适用` 之一 |
| `rules` | string[] | 引用的政策条款编号，使用当次政策的原始编号 |
| `missing` | string[] | 逐项列出需补充/核查的材料；没有则为空数组 |
| `reason` | string | 从事实与规则推导结论的过程，引用来源编号 |
| `customer_reply` | string | 面向客户的简短建议话术，不声称已执行 |

## 动作与字段的对应关系

| action | refund_cents | freight | missing |
|---|---|---|---|
| 退货退款 | 计算出的整数分 | 商家或买家 | 通常为空 |
| 直接退款 | 计算出的整数分 | 不适用（无需退回） | 通常为空 |
| 补发配件 | 0 | 商家（补发运费） | 通常为空 |
| 补充材料 | null | 待定 | 必须逐项列出缺失材料 |
| 物流核查 | null | 待定 | 列出需核验的凭据与流转记录 |
| 人工复核 | null | 待定 | 可为空，但须在 reason 说明触发原因 |

## 金额口径

```
refund_cents = 商品行原价总额 − 商品行分摊优惠 − 商品行历史退款
```

- 不允许用整单总额代替商品行金额。
- 不允许重复退还历史退款。
- 不另退原配送费。
- 三项任一未知 → 该单整体改为补充材料，金额 null、运费待定。
- 结果必须为非负整数；出现负数说明数据有问题，转补充材料或人工核查，不截断为 0。

## 写法要求

- `rules` 只写真实存在于当次政策中的编号；不同店铺编号不同，不套用其他店铺编号。
- `reason` 要能独立读懂：事实（含来源编号）→ 适用规则 → 结论。
- `customer_reply` 与结构化字段一一对应；待定类不出现金额与运费承诺。
- 不写入机器绝对路径、模型名、内部字段名或脚本细节。
- 同一批输出保存后不要覆盖已验收版本，除非用户明确要求覆盖。
