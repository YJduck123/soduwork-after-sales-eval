# 通用走查示例

示例仅演示推导方式，编号、金额、规则名均为占位，不对应任何真实店铺政策或订单。实际处理时必须读取当次政策中的条款编号与时限。

假设某政策包含：退货规则 R-RETURN（完好、非定制、签收后 N 小时内）、故障规则 R-FAULT（审核确认、M 小时内，商家承担运费）、金额规则 R-AMOUNT、缺失信息规则 R-MISSING、物流规则 R-LOGISTICS。

## 示例一：条件齐备的无质量问题退货

工单 T-01，客户称「不需要了，申请退货」。

- 订单记录 T-01-O：签收 3 月 1 日 09:00，申请 3 月 5 日 09:00，非定制，行原价 12000 分，分摊优惠 2000 分，历史退款 0 分。
- 审核记录 T-01-R：商品完好。

推导：连续间隔 96 小时（脚本 `elapsed_hours.py` 可算），在 N 小时内；商品完好且非定制 → 命中 R-RETURN，动作退货退款，运费由买家承担；金额 12000 − 2000 − 0 = 10000 分 → R-AMOUNT。

输出要点：`action=退货退款`、`refund_cents=10000`、`freight=买家`、`rules=["R-RETURN","R-AMOUNT"]`、`missing=[]`。回复写「建议退货退款，商品行可退 100.00 元，退回运费由您承担，最终结果以审核为准」。

## 示例二：只有口述、凭证未核实

工单 T-02，客户称「没声音，视频晚点发，先退款」。

- 审核记录 T-02-R：`fault_confirmed` 为 null，注明尚未收到凭证。

推导：客户主张不能当结论；故障条件未成立，不能走 R-FAULT；金额数据虽然完整，但当前缺的是证据而不是金额 → 动作补充材料，金额 null、运费待定，`missing` 写「故障视频或检测记录」。

输出要点：`rules=["R-MISSING","R-FAULT"]`。回复只说明缺什么、请客户补充，不出现金额与运费承诺。

## 示例三：签收争议

工单 T-03，客户称「物流显示签收，但我没收到」。

- 物流记录 T-03-L：状态已签收，签收凭据未核验（null），丢失未确认（false）。

推导：不能只凭「已签收」认定客户收到，也不能直接判定丢失 → 动作物流核查，金额 null、运费待定；`missing` 写「投递与签收凭据」「包裹流转记录」。

注意：若同一批还有「承运商正式记录已确认丢失」的工单，则直接退款、无需退回、运费「不适用」，不要与签收争议混为一谈。

## 示例四：金额字段缺失

某工单故障已确认且在时限内，但订单行的优惠分摊为 null。此时不能按整单价或 0 优惠估算，整体动作改为补充材料；`missing` 写「该商品行优惠分摊明细」，回复说明补齐后重新核算，且不承诺运费。

## 从示例到本批

上述示例只用于理解字段与规则的关系。处理真实批次时：

- 规则编号换成当次政策中的真实编号；
- 时限阈值换成当次政策的规定；
- 金额与结论一律从输入记录重新计算，不照搬示例数值。
