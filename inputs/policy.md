# 青禾数码演示店售后政策 v1

这是合成实验规则，仅供本次工单处理。所有时间为北京时间。金额以整数“分”记录。所有输出均是处理建议，不执行退款、发消息或变更订单。

## P01：事实与缺失信息

客户文字是诉求，不能自动当成已核实事实。只按带来源编号的订单记录、审核记录与物流记录判断。`null` 表示未知，不能补成有利于通过的值。作出结论所需资料缺失时，建议“补充材料”，逐项列出。物流争议优先按 P07 流转；已知超出适用期限或例外情形按相应规则转人工。

## P02：无质量问题退货

普通商品、完好状态已核实、从签收至申请不超过连续 168 小时（包含恰好 168 小时），建议“退货退款”，买家承担退回运费。超过 168 小时、定制商品或已核实不完好的无质量问题申请，建议“人工复核”，金额和运费待定。签收时间或完好状态未知，先“补充材料”。

## P03：功能故障

故障经审核记录确认，且从签收到申请不超过连续 720 小时（包含恰好 720 小时），建议“退货退款”，商家承担退回运费。此规则适用于促销和定制商品，不受“促销不退换”字样或普通退货 168 小时限制。只有客户口述或凭证未核实，先“补充材料”；已知超过 720 小时则“人工复核”。不自动同意客户提出的“仅退款不退货”。

## P04：错发商品

订单与实收型号不符且标签审核已确认，建议“退货退款”，商家承担退回运费。只有客户声称错发、缺少标签核验结果，先“补充材料”。

## P05：缺少配件

开箱资料已核实缺件，且库存记录显示可补发，建议“补发配件”，退款金额为 0，商家承担补发运费。已核实缺件但明确无法补发，建议“退货退款”，商家承担退回运费。开箱资料或库存情况未知，先“补充材料”。

## P06：退款金额

对本次涉及的商品行，建议退款金额 = 该行原价总额 − 该行分摊优惠 − 该行历史退款。不得用整单总额代替商品行金额，不得重复退还历史退款；不另退原配送费。三个金额均须明确且计算结果非负，否则“补充材料”，不猜优惠分摊或已退金额。已确认“退货退款”或“直接退款”但缺金额数据时，整体处理建议仍为“补充材料”，金额与运费暂不确定。

## P07：物流与空包争议

客户称未收货但物流显示签收，或只有重量异常的空包争议，建议“物流核查”，核验投递/签收凭据和包裹流转。不能只凭“已签收”认定客户已收到，也不能只凭重量异常判定丢件。承运商正式记录已经确认丢失，建议“直接退款”，无需退回，退回运费“不适用”，金额依 P06 计算。

## 输出约定

输出一个 JSON 数组，每个输入工单恰好一条，不遗漏、不增加工单。每条包含：

```json
{
  "case_id": "输入中的编号",
  "action": "退货退款 / 直接退款 / 补发配件 / 补充材料 / 物流核查 / 人工复核中的一个",
  "refund_cents": null,
  "freight": "商家 / 买家 / 待定 / 不适用中的一个",
  "rules": ["适用的政策编号，如 P03、P06"],
  "missing": ["具体需要补充或核查的材料；没有则为空数组"],
  "reason": "说明如何从输入事实与政策得到建议，引用来源编号",
  "customer_reply": "面向客户的简短回复，不声称已经退款或完成补发"
}
```

“退货退款”和“直接退款”填写计算出的整数分；“补发配件”填写 0；其余 action 填写 null。“补充材料”“物流核查”“人工复核”的 freight 为“待定”。
